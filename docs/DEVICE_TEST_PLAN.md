# Проверка на Android — отдельный этап

В текущей задаче приложение на эмуляторе/устройстве не запускалось. Начать этот план в новом чате по просьбе пользователя.

## Матрица

Минимально API 26, API 31/32 (ограничения touch overlay), API 34 и API 36. Желательно физическое устройство Samsung для игровых сценариев; S Pen в MVP не реализован.

## Сценарии

1. Чистая установка: ru, auto/mixed, auto provider, normal merge, auto contrast, 90% фон, 100% шрифт, medium button, кэш включён.
2. Отказать в overlay → понятное сообщение. Выдать через настройки → повторно включить.
3. Отказать в уведомлениях → захват и сервис не падают. Разрешить позже → состояние обновляется.
4. Отменить системное согласие на захват → выключенное состояние. Повторно согласиться → одна кнопка и foreground notification.
5. Выбрать полный экран. Нажать перевод 3 раза за сессию → системное согласие больше не запрашивается.
6. Тестовый экран: START, ゲームを続ける, 로그인, Player 01. Auto должен найти все области без дублей; подпись кнопки не должна попадать в OCR.
7. Диалог из трёх строк → один абзац. New Game / Settings / Exit → отдельные блоки. Две колонки не склеиваются.
8. Явный ja/ko: распознаются соответствующий текст и латинские имена. Менять режим объединения.
9. READY tap → немедленная обработка. Повторные tap игнорируются. TRANSLATED tap → полная очистка. Long press во всех состояниях → настройки.
10. Перетащить кнопку, перезапустить сессию; повторить в landscape. Координаты сохраняются отдельно.
11. Повернуть экран до кадра, во время OCR, во время сети и после перевода. Старые блоки исчезают; следующий снимок имеет правильные координаты.
12. Неподвижный экран: свежий кадр поступает после скрытия кнопки. Таймаут возвращает READY.
13. Нажимать и свайпать непосредственно по переводам в стороннем приложении. Отдельно API 31+, opacity 60/90/100%, несколько соседних блоков.
14. Светлая/тёмная область: автоматический контраст; проверить fixed dark/light и масштаб 80–130%.
15. Длинные переводы, мелкий исходный текст, близкие блоки, плотная сцена: читаемость/подбор/смещение без наложений.
16. Google, Yandex, Auto по отдельности. Искусственно недоступный Google → Auto переключается, явный Google — нет.
17. Повторяющиеся строки в нескольких местах → один сетевой перевод и несколько overlay. Повторить экран → кэш.
18. После прогрева отключить сеть: cached блоки видны, новые дают ошибку, успешные не исчезают. Пустой экран → без сетевых запросов.
19. Выключить во время capture/OCR/network. Нет оставшихся окон/уведомления/захвата/поздних результатов.
20. Остановить запись системным индикатором, отозвать overlay, завершить процесс → корректная остановка; новый запуск требует согласия.
25. Заблокировать и разблокировать экран (в том числе с активным переводом на экране и в игре с принудительной ориентацией): кнопка остаётся на месте, устаревшие переводы сняты. Если система остановила захват, кнопка показывает паузу, одно нажатие открывает запрос согласия и сессия продолжается без повторного включения в приложении.
26. Исключение из оптимизации батареи: строка состояния на главном экране обновляется после возврата из системного диалога; проверить поведение сессии при выключенном экране до и после исключения.
27. Плотный игровой экран с меню и цифрами: карточки остаются на своих строках, ничего не собирается в угол экрана, счётчики и проценты не переводятся.
28. Наклонённые в перспективе игровые панели и диалоги (Honkai Impact 3): карточки не перекрывают соседние карточки ни по горизонтали, ни по диагонали. Отдельно проверить блок, у которого сосед стоит справа-снизу.
29. Узкие кнопки с длинным русским переводом («Пропустить», «Начинать»): подпись остаётся одной строкой уменьшенным кеглем, без переноса по слогам, карточка центрируется на кнопке.
30. Режим правки: удержание кнопки при показанных переводах включает режим (кнопка становится голубой с галочкой, карточки получают рамку). Карточки перетаскиваются пальцем, касания не доходят до игры. Тап по кнопке выходит из режима, касания снова проходят насквозь, перевод остаётся на экране. Проверить на API 31+, что в режиме правки карточки становятся непрозрачными, а после выхода прозрачность возвращается к системному пределу.
31. Режим правки при поступлении частичных результатов перевода: перемещённые карточки не возвращаются на место при дорисовке. Новый перевод, поворот, блокировка экрана и остановка захвата сбрасывают режим правки и смещения.
32. **Знак поворота карточек проверить первым.** Наклонённая строка (панель в перспективе, повёрнутый баннер): карточка должна повернуться в ту же сторону, что и оригинал. Если наклон удвоился — знак угла в `OverlayRenderer.turned` инвертирован, поменять на `-label.angle`. Проверить наклон в обе стороны.
33. Плашка интерфейса: субтитр на тёмной полосе, кнопка на плитке, текст поверх арта. На плашке карточка должна получать её цвет, закрывать оригинал целиком и не вылезать за края плашки. Поверх арта поведение прежнее: полупрозрачная карточка выбранного контраста.
34. Тексты на градиентной или полупрозрачной плашке (диалоги Honkai Impact 3): плашка не должна «расползаться» на весь экран и не должна обрываться на первой же ячейке.
35. Настройки «Тёмный»/«Светлый» фон отключают подбор цвета по плашке, но ограничение геометрии плашкой остаётся. Прозрачность продолжает управлять фоном карточки.
36. Время обработки кадра: сравнить с прошлой версией на самом слабом целевом устройстве. Анализ кадра добавляет один проход масштабирования до `recycle`; заметного роста задержки быть не должно.
37. Проверить, что после очистки перевода и после остановки сессии сетка кадра не остаётся в памяти (карточки и `composition` сбрасываются в `reset()`).
38. Перенесённое предложение: диалог, где фраза занимает две строки и хвост — одно короткое слово. Должна получиться одна карточка с целым предложением, а не «…с помощью...» плюс отдельное «этот.». Проверить также хвост из двух-трёх слов и японский/корейский диалог, где регистра нет.
39. После ослабления порогов склейки перепроверить, что меню, колонки статистики и подписи кнопок по-прежнему не слипаются: главное меню, экран снаряжения, таблица наград.
40. ИИ, токен: вставить неверный токен → «Проверить подключение» даёт ✗ 401. Вставить верный → ✓ по всем строкам. «Показать»/«Скрыть»/«Скопировать»/«Очистить». Перезапустить приложение — токен сохранился; переустановить — не сохранился.
41. ИИ, список моделей: «Обновить модели» показывает только текстовые grok, без image/video/embeddings/multi-agent. Выбрать модель, перезапустить — выбор сохранён. Выбрать модель, затем вручную стереть её из списка (обновлением на другом ключе) — статус «модель больше недоступна», приложение не выбирает другую само.
42а. Проверка подключения: в блоке видно, какой провайдер и какая модель проверяются. Сменить проверяемую модель → модели перевода и заполнения глоссария не меняются, отчёт называет именно выбранную. Проверить модель одной роли, потом другой, потом ни одной из них — подпись под выбором каждый раз говорит правду о степени рассуждения. Очистить ключ — выбор сбрасывается.
42. ИИ, structured output: проверка подключения должна назвать транспорт (json_schema / json_object / только разбор). Прогнать проверку на нескольких моделях, включая reasoning-модель, и записать, какая что поддерживает.
43. ИИ, перевод: экран с разорванной строкой («Compensation o» + «f maintenance») → одна карточка на объединённой рамке с целой фразой. Экран меню (Settings / Exit / Account) → три отдельные карточки, ничего не слито.
44. ИИ, резерв: выключить сеть или испортить токен при режиме ИИ. При резерве «Google»/«Yandex»/«Авто» экран переводится обычным путём; при «Не использовать» — сообщение с причиной и ни одной карточки.
45. ИИ, отмена и поколения: повернуть экран и заблокировать его во время ответа модели (он медленнее веб-переводчика). Поздний ответ не должен дорисовываться поверх нового экрана.
46. ИИ, кэш: с выключенным восстановлением разрывов повторить тот же экран — второй раз без сетевого запроса. С включённым — запрос каждый раз, записей в кэше не появляется.
47. ИИ, приватность: logcat не должен содержать токен, OCR-текст, перевод и тело ответа модели. Проверить и при ошибках xAI.
48. Игры, выключено: при выключенном «Определять игру» переводить в нескольких приложениях — вкладка «Игры» остаётся пустой, на главном экране нет строки «Игра:».
49. Игры, доступ: включить «Определять игру» без доступа к статистике → сразу открываются системные настройки доступа. Выдать, вернуться — строка «✓ Доступ выдан». Отозвать доступ — перевод продолжает работать, просто без игры.
50. Игры, определение: перевести экран в игре → профиль появляется сам, на главном экране «Игра: <название>». Перевести на домашнем экране и в самом Lenslate — профилей для них не появляется. Переключиться между двумя играми и переводить по очереди — строка «Игра:» каждый раз правильная.
51. Игры, профиль: задать игре язык оригинала «Японский» — OCR в ней идёт японской моделью, в другой игре — как в общих настройках. Выключить «Учитывать эту игру» — перевод как без профиля. Удалить игру при включённом определении — появляется снова после следующего перевода в ней.
52. Игры, глоссарий: `Rapture → Рапчер`, `NIKKE → не переводить`, персонаж `Rapi → Рапи`. В ИИ-режиме экран с «Raptures approaching» даёт «рапчеры» в нужном падеже, NIKKE остаётся латиницей. Добавить дубликат термина в другом регистре — «Такой термин уже есть». Выключить «Контекст игры» на вкладке ИИ — глоссарий перестаёт действовать, а язык игры продолжает.
53. Игры, добавление вручную: поиск по названию и по package, добавление несуществующего package набором вручную, повторное добавление уже известной игры невозможно.
54. ИИ-заполнение, Grok и Gemini: на профиле известной игры «Заполнить профиль с ИИ» с веб-поиском → появляются источники, записи с метками «Официальная локализация / Принято у игроков / Предложение ИИ». Сохранить выбранное — записи в глоссарии, заметки дописаны после своих. Уже записанные термины не предлагаются повторно; расходящиеся по умолчанию не отмечены.
55. ИИ-заполнение, отказы: модель без поиска (например, grok-3 или gemma) — ответ приходит с пометкой «Модель отказалась от поиска». Неизвестная игра (выдуманный package) — «Игра не опознана», ничего не предлагается. Отмена во время работы и уход с вкладки: результат ждёт на профиле.
56. Степень рассуждения: на вкладке ИИ переключить «Рассуждение при переводе» на «Высокая» → «Проверить» показывает применённый уровень; перевод заметно медленнее. Для gemini-2.5-pro «Мин.» даёт бюджет 128, а не ошибку.
57. Память выбора модели: выбрать для перевода Grok и модель A, переключиться на Gemini и выбрать модель B, вернуться на Grok — снова A, у Gemini остаётся B. Перезапустить приложение — оба выбора на месте. Перевести экран сразу после переключения — запрос уходит к модели того же провайдера, «model not found» быть не должно.
58. Две роли: задать для перевода экрана одну модель, для заполнения глоссария — другую, у другого провайдера. Страница «Заполнить профиль с ИИ» показывает свою модель и своего провайдера; перевод экрана — свою. Очистить ключ одного провайдера — вторая роль продолжает работать.
60. Список моделей: у всех трёх провайдеров один диалог с поиском. «gem» → и gemini, и gemma; «claude sonnet» и «sonnet claude» → одно и то же; «gpt5» → gpt-5. Ни в одном списке нет моделей изображений, видео, звука, embedding и rerank.
61. Цена: у xAI и OpenRouter каждая строка показывает цену за 1M токенов и оценку за экран, у Gemini цены нет и ничего не выдумывается. Сверить две-три цифры с официальным прайс-листом. Выбор очень дорогой модели (например `openai/o1-pro`) спрашивает подтверждение; отмена не меняет выбор.
63. Живой предпросмотр: запустить заполнение профиля с поиском на каждом провайдере. Появляется стадия («Ищет в сети…» / «Размышляет…» / «Пишет ответ…»), текст растёт, счётчик символов идёт. Результат разбирается как раньше, источники на месте. Отмена во время потока — страница возвращается к настройкам, а не показывает «Сеть недоступна».
64. Виды записей: выбрать только «Локации» и «Фракции» в игре с известными персонажами → в предложениях нет людей ни под каким видом. Повторить для «Термины» без остального.
65. Ограничение источников: выключено по умолчанию. Включить  «до 3» и сравнить число источников в отчёте и расход в консоли провайдера с тем же запросом без ограничения. У Gemini ожидается пометка «не поддерживает», у xAI — либо применение, либо строка об отказе в отчёте без потери самого поиска.
66. xAI без рассуждения: модель без reasoning на `/chat/completions` (например grok-3) — перевод экрана работает (раньше запрос уходил без messages и падал).
62. OpenRouter: сохранить ключ с openrouter.ai, «Обновить модели» → сотни моделей, поиск в диалоге находит по вендору (`anthropic/`) и по названию. «Проверить» называет транспорт и применённое рассуждение. Перевод экрана моделью без reasoning и моделью с reasoning. Исчерпанный баланс/лимит — сообщение с причиной и включение резервного переводчика. Веб-поиск при заполнении профиля даёт источники.
21. FLAG_SECURE/чёрный кадр: распознавание запускается всегда; только если текста не найдено и кадр чёрный целиком, сообщение говорит о возможной защите экрана. Попытки обхода нет.
    Обратный случай: ночная сцена, экран чёрный на 90–95 %, светлая только короткая строка текста → текст распознаётся с первого нажатия, без сообщения о запрете захвата.
22. Очистить кэш, отключить кэш, сменить источник/цель/provider: записи не смешиваются.
23. Проверить, что изображения не появляются в файловой системе/галерее, HTTP содержит только текст, logcat не содержит OCR/переводов/ключей/SID.
24. Проверить Compose при большом системном шрифте, landscape, screen cutout, жестовой и трёхкнопочной навигации.

## Фиксировать результат

API, модель устройства, ориентация, настройки, шаги, ожидаемое/фактическое поведение. Не прикладывать чувствительные пользовательские скриншоты и logcat с текстом. Скриншоты специально созданной тестовой сцены допустимы только в рамках отдельно разрешённого тестирования.
