# Реализация MVP

## Pipeline

MainActivity → разрешения → foreground TranslationService → MediaProjection → VirtualDisplay / ImageReader → Bitmap → FrameAnalyzer + ML Kit → TextBlockReconstructor → LanguageResolver → SQLite / TranslationManager → OverlayRenderer.

Каждая операция получает generation. Поворот, настройки и остановка отменяют текущую операцию и инвалидируют результаты. Снимок освобождается сразу после OCR/яркости; продолжение pipeline содержит только текст и координаты.

## Захват

Системное согласие действует в пределах сессии. API 34+ запрашивает захват полного дисплея через MediaProjectionConfig. Один VirtualDisplay сохраняется всю сессию. Перед снимком кнопка скрывается, после небольшой задержки поверхность повторно присоединяется к существующему VirtualDisplay, чтобы запросить свежую композицию даже на неподвижном экране. Постоянный ImageReader listener закрывает неиспользуемые кадры, не сохраняя их.

Захват экрана обязателен: обычному приложению Android не даёт читать пиксели чужих окон, а альтернативы — AccessibilityService.takeScreenshot (API 30+, вне границ этого ТЗ и политики Play), системные разрешения или root. Согласие MediaProjection одноразовое и не сохраняется между сессиями.

Проекцию останавливает не только пользователь: блокировка экрана и системные политики делают это сами. В этом случае сервис не закрывается, а переходит в паузу — кнопка, уведомление и настройки остаются на месте, а нажатие кнопки открывает системный запрос согласия заново и переиспользует уже запущенный foreground service. Сохранённый Intent согласия при этом не используется: каждое подключение получает новое согласие. Перезапуск процесса не восстанавливает capture token.

Отдельная причина обрыва — выгрузка процесса системой при выключенном экране. Главный экран показывает состояние исключения из оптимизации батареи (`isIgnoringBatteryOptimizations`) и открывает системный запрос; оболочки со своими списками «спящих» приложений этим не покрываются.

Сервис слушает ACTION_SCREEN_OFF/ON и ACTION_USER_PRESENT. Выключение экрана снимает устаревшие переводы и отменяет текущую операцию, возвращение — заново привязывает окна оверлея (некоторые прошивки убирают их за время keyguard) и сверяет размер захвата с текущим размером экрана.

FLAG_SECURE не обходится; почти чёрные кадры и отсутствие текста обрабатываются отдельно.

## OCR

Модели Latin/Japanese/Korean и language-id поставляются в APK. Auto запускает три модели; ja/ko — соответствующую модель плюс Latin. Дополнительные исходные языки ограничены латинской письменностью. Китайский/деванагари доступны как язык результата, но отдельные OCR-модели для них не включены.

Первичны блоки ML Kit. Очевидные меню внутри одного блока разделяются; результаты моделей дедуплицируются по overlap, containment и сходству. Соседние блоки соединяются с учётом высоты, зазора, выравнивания, письменности, угла и пунктуации. Эвристики нуждаются в настройке по реальным играм, особенно для вертикального японского текста.

Движки, работающие с латиницей и кириллицей одновременно, пишут одно слово двумя алфавитами. Такое слово не переводится ни как русское, ни как английское, поэтому похожие буквы приводятся к алфавиту большинства букв слова; слово, оставшееся смешанным, не трогается. Строки без букв — счётчики, проценты, таймеры — не отправляются переводчику и не занимают место на экране.

## Сборка абзацев

Блоки распознавателя разбираются до строк, потому что разные модели проводят границы абзацев по-разному, и собираются обратно в `canMerge`. Одной геометрии для этого мало: последняя строка субтитра, состоящая из одного короткого слова, ниже и у́же предыдущей и отделена от неё полным межстрочьем — то есть не проходит ни по отношению высот, ни по зазору. Переведённые порознь половины дают две неверные фразы вместо одной верной.

Поэтому используются два внешних свидетельства. Первое — `paragraph`: индекс блока, в который строки положил сам распознаватель (`ScreenTextBlock.paragraph`, уникален в пределах модели). Второе — незакрытое предложение: первая строка не оканчивается терминальным знаком, а вторая начинается со строчной буквы, запятой или тире. Если хотя бы одно свидетельство есть, геометрические пороги ослабляются: зазор ×1.8, отношение высот до 1.9, горизонтальное перекрытие от 0.3, допуск по левому краю до 1.6 высоты строки.

Правило «две короткие подписи с заглавной буквы не сливаются» остаётся безусловным: одна нативная рамка ML Kit часто содержит целое меню, и его группировка не должна склеивать кнопки. Для CJK регистра нет, и там работает только `paragraph`.

## Перевод

Пакеты содержат до 900 символов, одну пару языков, один элемент массива на фрагмент. Поэтому соответствие ответов координатам сохраняется без ненадёжного разделения строк маркерами. Длинные абзацы разбиваются без разрыва surrogate pair и собираются обратно.

Google: публичный element.js → адрес актуального JS → X-goog-api-key → translateHtml (JSON protobuf). Загружаемый JS не исполняется. Домен найденного URL проверяется.
Yandex: JS виджета → SID; если виджет недоступен/без SID, публичный bootstrap переведённой страницы → SID → tr.json/translate.
Авторизация хранится 20 минут в памяти, обновляется при отказе; ошибки получения ограничены паузой. HTTP timeout до 15 секунд на запрос, один retry при временной сетевой ошибке.
Auto использует Google, затем Yandex; явный выбор не включает fallback. Одинаковые запросы делят один CompletableDeferred. Отмена coroutine отменяет OkHttp Call.
Ошибки отдельных фрагментов не скрывают успешные результаты; кэш отображается раньше сети. Недоступность сети не вызывает отдельный повтор для каждого блока в неудачном пакете.

SQLiteOpenHelper выбран как допустимый по ТЗ SQLite-вариант без генератора Room/KSP. Лимит — 20 000 записей. Отображаемый размер — оценка объёма текстовых данных, не размер страниц SQLite.

## Overlay

Один Canvas-слой для всех переводов и отдельное окно кнопки. Слой переводов использует FLAG_NOT_TOUCHABLE, поэтому его window alpha равна 1.0 и оригинальные глифы не просвечивают. Настройка 60–100% управляет alpha фона каждой карточки. Управляющее окно кнопки остаётся отдельным touchable-окном.

Координаты OCR — пиксели кадра, координаты оверлея — пиксели экрана. Пока виртуальный дисплей повторяет форму экрана, это одно и то же; при несовпадении формы (поворот дошёл только до одного из них) кадр содержит отмасштабированное и центрированное изображение, и `FrameMapping` снимает этот сдвиг. Без этого карточки уезжают от своего текста.

Геометрия карточек вынесена в `LabelLayout` и покрыта JVM-тестами. Карточка начинается с рамки распознанного текста: если перевод помещается в неё, размер шрифта подбирается двоичным поиском и рамка не меняется. Если не помещается, карточка растёт в свободный прямоугольник вокруг блока, ограниченный соседним распознанным текстом, уже размещёнными карточками, плашкой интерфейса и краем экрана. Свободный прямоугольник строится срезами: каждый мешающий сосед отрезает одну из четырёх сторон, и выбирается срез, который сохраняет исходную рамку и теряет меньше всего площади. Поэтому сосед по диагонали ограничивает рост так же, как сосед сбоку; при равной площади выигрывает более спокойный участок экрана. Однострочная подпись сначала пытается уместиться в одну строку уменьшенным кеглем и только потом переносится: разбитая по слогам кнопка нечитаема. Переносить перевод в другое место экрана или собирать всё в одну панель нельзя: положение — единственное, что связывает перевод с оригиналом. В предельном случае берётся минимальный шрифт, а перевод остаётся целым и на своём месте, даже если задевает соседа; меньшие карточки рисуются последними.

Короткий перевод по-прежнему перекрывает всю исходную область. Однострочный источник центрируется, абзац выравнивается по левому краю; тень под текстом сохраняет читаемость при полупрозрачном фоне.

## Композиция экрана

`FrameAnalyzer` масштабирует кадр до сетки примерно в 110 ячеек по длинной стороне и запоминает средний цвет каждой ячейки. Это делается в том же блоке, где работает OCR, и до `recycle`. Ячейка считается «детальной», если отличается от соседа справа или снизу больше чем на 26 по любому каналу: так отделяется плоский интерфейс от арта, глифов и границ.

`FrameAnalysis.panel` ищет плашку, на которой написан текст: опорный цвет берётся из недетальных ячеек кольца вокруг рамки текста, затем прямоугольник растёт построчно, пока в новой строке или колонке хотя бы 75% ячеек остаются в пределах 30 от опорного цвета. Опорный цвет плавно смещается к принятым ячейкам, поэтому градиент и наклонная поверхность проходят, а жёсткая граница диалога останавливает рост. Рост ограничен семикратным размером текста, а результат меньше 1.6 площади текста плашкой не считается. Внутри `average` намеренно проверяется только цвет: ячейки вплотную к глифам всегда «детальные», но это по-прежнему поверхность, на которой глифы написаны.

Найденная плашка даёт три вещи: границу для роста карточки, её цвет (в режиме автоматического контраста) и закраску оригинала — перед отрисовкой карточек их следы заливаются цветом плашки непрозрачно, поэтому английский текст не просвечивает сквозь полупрозрачный фон. Если плашки нет, текст лежит на арте, и поведение остаётся прежним.

`FrameAnalysis.quiet` даёт долю недетальных ячеек области и используется как весовой множитель при выборе среза свободного прямоугольника.

Сетка — производная кадра и подчиняется тем же правилам: только память, никакой сети, диска и логов; сбрасывается вместе с переводами в `OverlayRenderer.reset`.

## Наклонённый текст

ML Kit сообщает угол строки и вертикальную рамку вокруг неё. Для наклонной строки эта рамка заметно больше самого текста, поэтому упрощённая карточка на ней выглядит смещённой. `LabelLayout.oriented` восстанавливает собственную рамку текста из угла и вертикальной рамки: `W = w·cos + h·sin`, `H = w·sin + h·cos` решается относительно `w` и `h`. Углы меньше 4° считаются шумом распознавания, больше 32° — областью, где решение системы теряет устойчивость; в обоих случаях наклон игнорируется. Наклонная карточка центрируется по центру текста (единственная точка, которую поворот оставляет на месте), а соседям предъявляется её вертикальная габаритная рамка. Рисуется через `canvas.rotate`.

Знак угла ML Kit не подтверждён на устройстве. Если карточки будут наклоняться в противоположную сторону, правка — один символ в `OverlayRenderer.turned`; это первый пункт соответствующего раздела DEVICE_TEST_PLAN.md.

## Проверка протоколов

08.09.2026 выполнены отдельные HTTP-пробы с искусственными фразами “Mission Complete” и “New Game”. Google и Yandex вернули переводы на русский. Старый фиксированный Google JS уже не содержал нужный ключ: реализация использует актуальный script URL из element.js. Это проверка протокола с компьютера, не интеграционный тест Android, устройства или конкретной сети пользователя.

## Проверить на устройстве

Сборка и JVM-тесты не подтверждают MediaProjection, OCR native-модели, повороты, drag, tap-through, режим правки, знак угла наклона, реальные цвета плашек, accessibility или фактическую разметку Compose. Эти проверки сознательно отложены пользователем. См. DEVICE_TEST_PLAN.md.
